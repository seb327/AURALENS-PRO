# AuraLens (working name)

Premium spirituality and wellbeing app: symbolic Mien Shiang–inspired aura readings from a front-camera scan or 3 uploaded photos. Built with Expo, React Native, TypeScript, expo-router.

> Public-facing name is configurable. Change `APP_DISPLAY_NAME` in `.env` (or directly in `app.config.ts`) without editing any screen code.

### Configuring Aura Buddy

```bash
# 1. Deploy the function
supabase functions deploy ai-buddy

# 2. Set provider secrets
supabase secrets set \
  AI_PROVIDER=anthropic \
  ANTHROPIC_API_KEY=sk-ant-... \
  AI_MODEL=claude-3-5-sonnet-latest
# (or AI_PROVIDER=openai + OPENAI_API_KEY=sk-...)
```

If you skip step 2, the function still runs and returns a deterministic local-fallback response so the chat surface never breaks.

See [`docs/supabase-setup.md`](docs/supabase-setup.md#ai-buddy-phase-24--live) for the full request lifecycle, the strict data-passing contract, and a local `curl` test.

### Configuring RevenueCat

1. Create a project at https://app.revenuecat.com
2. Add products in App Store Connect and Google Play Console:
   - `auralens_instant_reading_099` — Consumable, £0.99
   - `auralens_monthly_999` — Auto-renewable subscription, £9.99/month
3. In RevenueCat:
   - Create an entitlement called `monthly` and attach `auralens_monthly_999` to it
   - Create an offering (e.g. `default`) and add packages for both products
4. Copy the iOS and Android **public SDK keys** from RevenueCat → API Keys
5. Add to `.env`:

   ```
   REVENUECAT_IOS_KEY=appl_xxxxxxxx
   REVENUECAT_ANDROID_KEY=goog_xxxxxxxx
   ```

6. Add the native SDK in a development build:

   ```bash
   npx expo install react-native-purchases
   eas build --profile development --platform ios
   # or
   eas build --profile development --platform android
   npx expo start --dev-client
   ```

In Expo Go (no native modules), the app uses simulated purchases so every flow stays clickable. A banner on the pricing screen makes this obvious.

### App Store / Play Store setup notes

- **App Store Connect**: create the consumable and the auto-renewable subscription, attach them to the same subscription group as future tiers if you plan to expand. Submit them for review alongside the binary, or earlier as a draft. TestFlight builds can purchase sandbox products immediately once they're "Ready to Submit".
- **Google Play Console**: create the one-off as an in-app product (Managed product → Consumable), and the subscription as a Subscription with a single base plan. Internal-testing track works as soon as the product is "Active" and your tester opt-in URL has been used.
- **Compliance**: do not present Stripe Checkout for digital aura readings inside the iOS or Android app. Stripe may still be used for a future web checkout.

### Testing purchases

- **Local (Expo Go)**: the stub purchase service unlocks credits / monthly without contacting any store. Use this to verify every flow renders.
- **iOS TestFlight**: create a sandbox tester in App Store Connect → Users and Access → Sandbox Testers. Sign out of the App Store on the device, then make a sandbox purchase. RevenueCat dashboard will show the customer.
- **Android internal testing**: add testers to the internal track and to the License Testers list in Play Console → Setup. Install via the opt-in link; sandbox purchases will not be charged.

### Running with real face landmarks (dev build)

The native analyzer is wired but is intentionally lazy-loaded so the project still runs in Expo Go.

```bash
# 1. Install EAS CLI once
npm i -g eas-cli

# 2. Add the native module
npx expo install @react-native-ml-kit/face-detection

# 3. Create a development build (one-time per device)
eas build --profile development --platform ios
# or
eas build --profile development --platform android

# 4. Run the dev client against the bundler
npx expo start --dev-client
```

In Expo Go the heuristic analyzer is used automatically — no install required. You can verify which analyzer ran by inspecting `reading.imageQuality` against `result.analyzer` returned by the service.
